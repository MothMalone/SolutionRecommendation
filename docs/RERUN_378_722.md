# Rerunning arm 0 on 378 and 722, and the full ACORec pass

## Why these two failed, and what changed

| | what happened | fix |
|---|---|---|
| **722** | hit the wall-clock cap twice (convergence attempt + explicit-budget retry), 6549s spent, **nothing recorded**. AutoDP checks its budget only *between* MCTS iterations, so one slow operator (AD dedup is O(n²), LOF, MICE) overruns any cap. | `SearchCheckpoint` writes the running-best pipeline after every completed iteration. A kill now salvages that pipeline **apply-only** — one pass, not a re-search. |
| **378** | segfaulted (`rc -11`) **in AutoGluon scoring**, after the search had already succeeded. The crash killed `adp_bench` itself, and the `finally: rmtree(scratch)` deleted 55 minutes of finished search. | Scoring runs in a child process. A crash raises `ScoringCrashed`, the prepared frame is **copied out** for re-scoring, and the row records `eval_crashed`. |

Both fixes are disclosure-preserving: a salvaged row carries `salvaged_from_checkpoint: true`, and
both summarizers refuse to let it average silently.

## Arm 0 on 378 and 722

Give these a **generous cap** — they are the two largest frames in the set, and the point of the
checkpoint is that a cap kill is no longer fatal, so a big cap costs nothing when the search
converges early.

```bash
python scripts/run_arms.py --arm 0-adp-baseline --datasets 378 \
    --out /kaggle/working/arms_0_378.jsonl --protocol leakfree \
    --time-limit 300 --cap-seconds 5400 --data-dir data/eval_datasets

python scripts/run_arms.py --arm 0-adp-baseline --datasets 722 \
    --out /kaggle/working/arms_0_722.jsonl --protocol leakfree \
    --time-limit 300 --cap-seconds 5400 --data-dir data/eval_datasets
```

Run them in **separate notebooks** — each writes its own file and they concatenate.

### Read the result before you put it in the table

```bash
python scripts/run_arms.py --summarize "/kaggle/working/arms_0_*.jsonl"
```

Three flags now matter, and each changes what the number means:

- `!! ... EMPTY pipeline` — **AutoDP selected no preprocessing**, so the score is the raw frame.
  This is not "AutoDP chose to do nothing"; the explicit-runTime retry produces it on large frames
  whenever the budget expires before the first iteration completes. A forced cap kill on 378
  reproduced exactly this. **Do not average these as search results.**
- `!! ... SALVAGED from a cap-killed search` — the pipeline is the best of the iterations that
  *did* complete, not of a converged search. Reportable, but disclose it.
- `!! ... search-iteration exceptions` — pre-existing check; their MCTS swallows exceptions in a
  bare `except:`, so a "converged" run may never have evaluated anything.

If 378 or 722 comes back `eval_crashed`, the search is **not** lost — the prepared frame is at the
`prepared_dir_kept` path in the row, and only the AutoGluon scoring needs redoing.

## Full ACORec pass

The REF configuration is applied automatically by `--acorec-config ref` (the default); do not add
the flags by hand.

```bash
# 4 shards, one per notebook
python scripts/run_arms.py --arm 1-aco-theirops --shards 4 --print-commands --protocol leakfree
```

Sharded runs are resumable — a notebook that times out can simply be restarted, and completed
rows are skipped.

**Check `eval_method` before averaging.** The summarizer flags any row whose `eval_method` is not
`autogluon`; `proxy` and `autogluon_failed` rows are not AutoGluon scores and must be excluded.

## Before spending the compute

`docs/SIGNAL_DIAGNOSIS.md` argues that a rerun of the current configuration will land where the
current table already is, and that the accuracy is in proxy fidelity (worth ~4× everything
metafeature retrieval contributes) rather than in another pass of the same setup. The two-dataset
arm-0 rerun is worth doing regardless — it fills real holes in a published column. The full ACORec
rerun is worth deferring until at least the proxy change in §B of that document is measured on
reference-holdout.
